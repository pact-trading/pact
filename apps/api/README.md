# Settle API

Hono API for Settle checkout on Whitechain. Run `pnpm install`, `pnpm typecheck`, and `pnpm test` in this directory. `pnpm dev` starts the API; `example.env` lists configuration. The fake chain is the default. Set `CHAIN_ADAPTER=viem`, `RPC_URL`, `RELAYER_PRIVATE_KEY`, and all four contract addresses to use the live adapter.

Optional [Privy identity](PRIVY.md) accepts verified access tokens for merchant registration and merchant-scoped API access. Configure `PRIVY_APP_ID` and server-only `PRIVY_APP_SECRET`; the SDK supports a fresh `getAccessToken` callback per request. Browser login and real-provider acceptance remain separate integration steps.

[Merchant settings](MERCHANT_SETTINGS.md) expose checkout branding and a 30-day default refund window. New payments snapshot that window, and signed charge/authorize calls must match it. Confirmed refund deadlines come from escrow state at the event block. Payout remains the bound merchant wallet; configuring a separate recipient is not implemented.

Set `BOOTSTRAP_MERCHANT_ADDRESS` on first start to create a merchant and print a publishable and secret API key once. Use `Authorization: Bearer <key>`. Publishable keys can create and read payments, read checkout configuration and plans, register a signed mandate, and submit signed intents. Secret keys can use all routes. Mutations accept `Idempotency-Key`; repeated requests return the stored response and conflicting payloads return 409.

`POST /v1/intents` accepts the SDK's `IntentRequest` with decimal strings for bigint values. `POST /v1/payments/:id/refund` requires `amount`, `reason`, and the signed `intent`, `signature`, and `data` for the escrow refund call. `GET /v1/refunds`, `GET /v1/subscriptions`, and `GET /v1/refusals` return merchant scoped records. `POST /v1/subscriptions` registers a signed mandate; the keeper renews due subscriptions. `POST /v1/subscriptions/:id/renew` exposes an early refusal reason, and `POST /v1/subscriptions/:id/cancel` requires a signed payer intent. Payment and refund status changes after indexed chain events. The offline fake adapter emits and indexes these events automatically when started by `src/server.ts`.

Run `../scripts/e2e.sh` for an offline HTTP lifecycle check. It boots the API, seeds a merchant, pays, partially and fully refunds, and checks that a third refund is refused.

The indexer, approval reconciliation and webhook delivery each run every second with independent in-flight guards; the keeper runs every 15 seconds. A slow RPC cannot stop delivery of already queued events. Up to 50 due webhook deliveries start concurrently, so one slow merchant destination does not serialize everyone behind its five-second timeout. Confirmation depth and external RPC/webhook latency still affect end-to-end timing; the running service must be restarted deliberately to use this scheduler.

After building `../contracts` with `forge build`, run `pnpm test:router-gas` for an offline compatibility check. It passes execution budgets calculated by the API into Foundry tests of the actual Router for charge, refund, and the target gas ceiling. It needs Foundry but no RPC or funded wallets.

The x402 routes remain closed until Permit2 and the exact and upto proxy addresses are configured and checked on chain. `/supported` advertises no schemes; `/verify` and `/settle` return 501. Invoice financing (`src/financing/`) runs when `RECEIVABLES_ADDRESS` and `INVESTOR_REGISTRY_ADDRESS` are set; without them `POST /v1/invoices/:id/list` returns 501 `financing_unavailable`. See `docs/live-mode.md#invoice-financing`.

Sponsored transaction gas is explicit: target `maxGas` + `maxGas / 63` EIP-150 headroom + 200,000 gas for validation and cold storage + the updated Router's 120,000 gas settlement reserve + encoded transaction intrinsic gas. This covers both the deployed early guard and the updated late forwarding guard. The API refuses transaction limits above the configured target ceiling + 400,000. It simulates with that exact gas and gas price, requires `execute` to return true, and broadcasts with the same values. It does not use `eth_estimateGas` for Router execution because a nonreverting `Refused` event can be cheaper than execution. The minute budget reserves the entire transaction cost; the tank check conservatively covers transaction gas plus the Router's 40,000 reimbursement overhead. Submissions are serialized within one API process to protect nonce and budget allocation. Run only one live process per relayer key.

Indexed Router events match the submitted transaction, signer, nonce and merchant. `Executed` confirms the intent and records reimbursement and USDT fees. `Refused` records a named reason; unpaid charge attempts become `financialStatus: failed`, and refused refunds become `failed`, releasing their pending reservation. Captured/refunded amounts come only from matching escrow events. Partially refunded payments retain `status: succeeded`. Exports use confirmed accounting entries; historical databases require an audited receipt backfill before export. Fees and token-balance deltas are distinct when the fee vault is the merchant itself. See [accounting and backfill](ACCOUNTING.md).

All relayer submissions share the durable account writer: operation identity and domain reservations commit before preparation; nonce and locally calculated transaction hash commit before broadcast. Preparation failures can release unused reservations. Broadcast timeouts retain their hash and block conflicting sends until receipt reconciliation; a missing receipt never proves failure. Startup retires only operations that provably never crossed the broadcast boundary. Legacy unjournaled operations require explicit audited recovery. This requires exactly one API/keeper process per relayer key; stop the old process before binding its database in a replacement process.

Intent retries return the original result only for the same authenticated merchant and exact normalized signed request. Reusing a payer nonce with a different merchant, calldata, signature or signed field returns `replay` without disclosing the original intent. Identical retries remain readable after confirmation and never submit again.

Hosted approval is separately opt-in. `scripts/check-checkout-approval.ts` exercises a newly created local Anvil fork, synthetic payer/relayer keys, deployed official-token/delegate bindings, exact 2 USDT approval and charge with zero payer WBT. This is local integration evidence, not an actual email/passkey authentication flow or live activation.

`SUBSCRIPTION_VERSION` defaults to `1`. Version `2` requires a V2 deployment address and merchant consent on registration. Cancellation accepts the payer's V2 `Cancel` signature without requiring merchant tank funding. A durable database binding prevents accidental reinterpretation of existing subscription rows after an address/version switch. See [V2 contract/API integration](../contracts/SUBSCRIPTION_V2.md). The running V1 process has not been switched. `scripts/check-subscription-v2.ts` verifies the new API path on an isolated official-token fork.

Relayer spend reservations persist across process restarts and sum across intents, approvals and direct subscription writes. They reserve the full gas-price ceiling before broadcast and retain it for uncertain, reverted and confirmed writes; only provably unsent operations release their cost. Direct subscription transactions enforce a one-million gas ceiling and 100 gwei fee ceiling. The shared per-minute budget is 0.01 WBT by default. This is relayer float protection, not proof of merchant reimbursement for direct keeper calls.

`RELAYER_MIN_AMOUNT_MINOR` defaults to `1000000` (1 USDT) and must agree with the Router policy. Testing a 0.5 USDT sponsored refund requires both the API and Router minimum to allow `500000`. The live verification script temporarily lowers only that Router setting and restores the original value in cleanup; it preserves the other limits.

If contract artifacts are already built elsewhere, set `CONTRACT_ARTIFACTS_DIR` to that Foundry `out` directory. It is read-only; this lets API tests run in a backend-only worktree without rebuilding or changing contracts. API signing helpers are local so API typecheck does not require installing SDK dependencies.

Run the official-token preflight with `WALLET_ENV_PATH=/absolute/path/to/.env.wallets pnpm exec tsx scripts/live-api-flow.ts`. It verifies chain 1874, the deployed token bindings, six decimals, balances, settings and the original GasLimit refusal. Add `LIVE_EXECUTE=1` only to execute the funded test: 1 USDT charge then 0.5 USDT refund through real HTTP endpoints. It uses port 3002 (override with `LIVE_API_PORT`, never 3000/3001), a fresh temporary SQLite database, existing deployments, and only missing token approvals. It verifies Router and escrow events, two-confirmation API statuses, on-chain amounts, payer balance changes and fee-adjusted exports. It writes a credential-free `result.json` beside the temporary database and prints that path. Wallet secrets are read into memory, never written by the script. On completion the HTTP server is closed.
